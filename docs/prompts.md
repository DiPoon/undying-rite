# 작업 프롬프트

구현을 맡길 때 붙여 넣는 프롬프트입니다. 설계의 내용은 `CLAUDE.md`와 `docs/`의 문서에 있고, 프롬프트는 어느 마일스톤을 어떤 기준으로 끝낼지만 전합니다.

**쓰는 법**
- 이 폴더에서 새 세션을 열고 모델을 Opus로 바꾼 뒤 붙여 넣습니다. `CLAUDE.md`는 세션이 시작될 때 자동으로 읽힙니다.
- 마일스톤 하나를 세션 하나에서 진행합니다. 세션이 중간에 끝났으면 맨 아래의 "이어가기"를 씁니다.
- 마일스톤이 끝나면 보고에 적힌 방법으로 직접 해 보고(`docs/milestones.md`의 사람 확인), 괜찮으면 다음 마일스톤으로 넘어갑니다.
- 커밋을 원하지 않으면 각 프롬프트의 커밋 문장을 지우고 보내면 됩니다.

## M0. 네트워크 골격

```
docs/milestones.md의 M0(네트워크 골격)을 진행해 주세요.

이 저장소에는 아직 코드가 없고 설계 문서만 있습니다. CLAUDE.md를 따라 docs/milestones.md와 docs/architecture.md를 먼저 읽고, docs/design.md는 4절(맵), 5절(이동과 충돌), 12절(수치)을 읽어 주세요. 나머지 규칙은 M1부터 씁니다.

이 기기에는 Rust가 설치되어 있지 않으니 rustup으로 설치해 주세요. 홈 디렉터리의 ~/.rustup과 ~/.cargo에 설치되고 셸 프로필에 경로가 추가되는 것은 알고 있습니다.

M0의 목적은 게임을 만드는 것이 아니라, 서버 권위 구조에서 자기 캐릭터의 이동이 지연 속에서도 매끄럽다는 것을 확인하는 것입니다. 이후의 모든 규칙이 이 구조 위에 올라가므로 다음 네 가지에 특히 신경 써 주세요.

- 게임 규칙은 crates/shared에 Rust로 한 벌만 있고, 서버는 네이티브로, 브라우저는 WebAssembly로 같은 코드를 실행합니다. web/의 TypeScript는 Rust가 돌려준 값을 그리고 입력을 넘기기만 합니다. 이 경계가 M0에서 굳으므로, TypeScript가 계산을 떠맡는 일이 없게 해 주세요.
- 시간은 틱으로만 세고, shared는 같은 입력에 같은 결과를 냅니다. 네이티브와 WebAssembly 사이에서도 같아야 합니다.
- 화면 없는 테스트 클라이언트가 브라우저와 같은 client-core를 써서 예측 오차를 숫자로 잴 수 있어야 합니다. 화면을 보지 않고도 구조가 맞는지 확인하는 수단이고, 뒤 마일스톤에서도 계속 씁니다.
- 빌드 산출물은 /mnt/e가 아니라 WSL 홈 아래에 쌓여야 합니다. /mnt/e는 파일 쓰기가 매우 느려서, 산출물이 거기에 쌓이면 빌드가 쓸 수 없을 만큼 느려집니다.

끝난 상태는 docs/milestones.md의 M0 작업이 모두 체크되고 자동 확인이 전부 통과한 것입니다. 통과하지 못한 항목이 있으면 출력과 함께 그대로 알려 주세요.

저장소는 git init으로 초기화하고, 자동 확인이 통과한 시점에 로컬에 커밋해 주세요. 원격 저장소는 만들지 않습니다.

마지막에 docs/milestones.md의 현재 상태와 진행 기록을 고치고 CLAUDE.md의 명령어 절을 채운 뒤, 다음 순서로 보고해 주세요.
1. 된 것과 안 된 것
2. 자동 확인의 실제 출력
3. 제가 브라우저로 직접 확인하는 방법 (실행 명령, 지연을 주입하는 방법, 무엇을 보면 되는지)
4. 구현하면서 문서의 빈 곳을 메운 결정
```

## M1. 1대1 추격

```
docs/milestones.md의 M1(1대1 추격)을 진행해 주세요. M0는 제가 직접 확인했습니다.

CLAUDE.md를 따라 docs/milestones.md의 진행 기록부터 읽고, docs/design.md는 4~8절, 11절, 12절을 읽어 주세요. 수명 게이지, 구속, 리스폰, 목표는 M2의 범위라 이번에는 만들지 않습니다.

M1은 이 게임에서 가장 중요한 관문입니다. 탑다운에서 쫓고 쫓기는 것이 재미있는지를 제가 직접 해 보고 판단하고, 재미가 없으면 뒤 단계를 진행하지 않습니다. 그러니 이번 결과물은 제가 수치를 바꿔 가며 추격을 반복해 볼 수 있는 시험장이어야 합니다.

어려운 지점은 셋입니다.

- 판정의 순서. 공격 적중, 판자 기절, 넘기가 0.1초 안에서 겹칩니다. docs/design.md에 정한 규칙(같은 틱의 적중과 기절은 둘 다 성립 등)이 틱 처리 순서 때문에 달라지지 않게 하고, 경계 사례를 단위 테스트로 고정해 주세요.
- 시야로 거른 상태 전송. 보이지 않는 상대는 메시지에 아예 없어야 합니다. 화면에서만 가리는 구현은 통과가 아닙니다. 정보 누출 테스트로 확인해 주세요.
- 살인마와 생존자의 충돌. 서로 막기만 하고 밀어내지 못해야 하고, 예측과 어긋날 때 화면이 떨리지 않아야 합니다. 완벽하지 않아도 되지만, 보정 크기를 기록해서 어느 정도인지 숫자로 보여 주세요.

맵 초안과 루프 시뮬레이터도 이번 범위입니다. 시뮬레이터 결과에서 살인마 봇이 끝내 맞히지 못하는 구조물이 나오면 맵이나 수치의 문제이니, 임의로 규칙을 바꾸지 말고 원인을 분석해 보고해 주세요. 구조물의 크기나 판자 위치를 고치는 것은 괜찮습니다.

끝난 상태는 M1 작업이 모두 체크되고 자동 확인이 전부 통과한 것입니다. 자동 확인이 통과한 시점에 로컬에 커밋해 주세요.

마지막에 docs/milestones.md를 고치고 다음 순서로 보고해 주세요.
1. 된 것과 안 된 것
2. 자동 확인의 실제 출력과 루프 시뮬레이터 결과 표
3. 제가 1대1로, 그리고 혼자 봇을 상대로 해 보는 방법
4. 추격 길이에 가장 크게 영향을 주는 수치 다섯 개와 각각 어느 방향으로 바꾸면 어떻게 되는지
5. 구현하면서 문서의 빈 곳을 메운 결정
```

## M2. 4인 라운드

```
docs/milestones.md의 M2(4인 라운드)를 진행해 주세요. M1의 추격은 제가 해 보고 계속하기로 했습니다.

CLAUDE.md를 따라 docs/milestones.md의 진행 기록부터 읽고, docs/design.md 전체와 docs/architecture.md 4절, 5절, 8절, 9절을 읽어 주세요.

범위가 넓으니 다음 순서로 진행해 주세요. 앞 단계가 자동 확인으로 굳기 전에 뒤 단계로 넘어가면 화면에서 버그를 찾느라 시간을 쓰게 됩니다.

1. shared의 규칙과 단위 테스트. 수명 게이지, 구속, 구출, 소생, 치료, 보호, 전원 무력화, 사망과 리스폰, 목표, 승패와 시간 판정, 익명화.
2. 봇과 화면 없는 라운드. 봇 넷(살인마 1, 생존자 3)이 라운드를 끝까지 돌 수 있을 때까지. 여기서 규칙의 빈 곳과 교착이 대부분 드러납니다.
3. 기록, 리플레이 검증, 지표 요약.
4. 서버의 대기실과 재접속, 그리고 클라이언트 화면.

한 세션에 다 끝나지 않아도 됩니다. 단계가 끝날 때마다 자동 확인을 통과시키고 로컬에 커밋한 뒤 docs/milestones.md의 진행 기록을 남겨서, 어느 시점에 멈춰도 다음 세션이 이어받을 수 있게 해 주세요.

특히 봐 주셨으면 하는 것은 정보 공개 범위입니다(docs/design.md 11절). 살인마에게 가는 메시지에 생존자가 누구인지, 수명 게이지가 얼마인지, 어느 리스폰 지점을 골랐는지가 어떤 형태로든 들어 있으면 안 됩니다. 사건 메시지와 식별자를 통한 간접 누출까지 테스트로 확인해 주세요.

화면 없는 라운드 200회의 결과에서 라운드가 한쪽으로 크게 기울어 있더라도 수치를 맞추려고 하지는 말아 주세요. 봇의 실력은 사람과 다르고, 밸런스는 M3에서 사람이 해 보며 맞춥니다. 다만 라운드가 끝나지 않거나 한 가지 종료 조건만 나오는 경우는 규칙이나 봇의 결함일 수 있으니 원인을 알려 주세요.

마지막에 다음 순서로 보고해 주세요.
1. 된 것과 안 된 것
2. 자동 확인의 실제 출력과 봇 라운드의 지표 표
3. 제가 봇과 함께, 또는 다른 사람과 함께 라운드를 해 보는 방법
4. 구현하면서 문서의 빈 곳을 메운 결정과, 규칙 자체에 문제가 있다고 본 지점
```

## M3. 플레이테스트 지원

플레이테스트 단계에서는 그때그때 필요한 것을 요청합니다. 아래는 자주 쓸 형태입니다.

**수치 조정**
```
플레이테스트에서 [관찰한 현상]이 있었습니다. var/ 아래의 라운드 기록에서 관련 지표를 뽑아 실제로 그런지 확인하고, config/balance.toml에서 바꿀 만한 수치와 예상되는 부작용을 제안해 주세요. 아직 수치를 바꾸지는 말고 제안만 해 주세요.
```

**버그**
```
[재현 상황]에서 [기대한 것] 대신 [실제로 일어난 것]이 일어났습니다. 해당 라운드 기록은 [파일]입니다. 리플레이 검증 도구로 재현해 원인을 찾고, 그 경우를 고정하는 단위 테스트를 먼저 추가한 뒤 고쳐 주세요.
```

**접속 방법**
```
친구 세 명이 제 방에 들어올 수 있게 하려고 합니다. 가능한 방식들의 장단점과 필요한 작업을 정리해 주세요. 외부에 공개되는 일이니 제가 방식을 고르기 전에는 실행하지 말아 주세요.
```

## 이어가기

세션이 마일스톤 도중에 끝났을 때 새 세션에서 씁니다.

```
docs/milestones.md의 현재 마일스톤을 이어서 진행해 주세요. 진행 기록의 가장 최근 항목과 체크박스가 지난 세션이 남긴 상태입니다. 먼저 전체 검사 명령을 돌려 지금 상태가 기록과 맞는지 확인하고, 맞지 않으면 그것부터 알려 주세요. 그 뒤 남은 작업을 진행하고, 끝낼 때는 그 마일스톤 프롬프트에 정한 순서대로 보고해 주세요.
```
